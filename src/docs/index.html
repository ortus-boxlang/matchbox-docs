What is MatchBox?

Write expressive, dynamically typed BoxLang, then run it locally or package it for a specific deployment target. The native runtime is implemented in Rust rather than Java. Standalone builds combine your compiled bytecode with a runner, so the destination machine does not need a separate MatchBox installation.

MatchBox complements the JVM runtime. It is useful for command-line tools, browser applications, native web services, and resource-constrained devices. Choose the JVM runtime when you need its complete Java ecosystem and integration surface.

How it works

  1. Parse. The Pest-based parser reads BoxLang source.
  2. Compile. The compiler produces compact bytecode, with tree-shaking for the prelude.
  3. Execute. A stack-based VM runs the bytecode with cooperative fibers. The native CLI also includes a tiered JIT.
  4. Package. A target-specific runner carries the VM and your program to its destination.

See JIT & architecture for the distinction between the native CLI, lean runner stubs, and other targets.

A growing BoxLang implementation

Core syntax is familiar, but complete JVM parity is not implied. Libraries, runtime APIs, and hardware capabilities differ by target. Start with the compatibility guide and test on your intended runtime.
