The official image

docker pull ghcr.io/ortus-boxlang/matchbox:latest

The image uses matchbox as its entrypoint and /app as its working directory. Arguments after the image name go directly to the CLI.

Run a script

docker run --rm -v "$PWD:/app" ghcr.io/ortus-boxlang/matchbox:latest hello.bxs

These examples use a Unix shell. Substitute an absolute host path when using another shell. Mount a project directory, not an entire home directory; the program can access files in the mount.

Build into the mounted directory

docker run --rm -v "$PWD:/app" ghcr.io/ortus-boxlang/matchbox:latest --build hello.bxs

docker run --rm -v "$PWD:/app" ghcr.io/ortus-boxlang/matchbox:latest --target native hello.bxs

A native executable produced by the Linux container targets Linux, not the host's macOS or Windows environment. Match the target architecture and system requirements as well.

Serve a webroot

docker run --rm \
  -p 127.0.0.1:8080:8080 \
  -v "$PWD/www:/app" \
  ghcr.io/ortus-boxlang/matchbox:latest \
  --serve --host 0.0.0.0 --port 8080 --webroot /app

Open http://localhost:8080. The process binds to 0.0.0.0 inside the container so Docker can forward requests. This example publishes the port only on the host's loopback address. Change the host binding deliberately when exposing the service to other machines.

Choose a tag

TagMeaning
latestMost recent stable release image.
vX.Y.ZA specific published release. Replace with an existing tag.
developRolling development image.
snapshot, beRolling development aliases.

Pin a release tag or image digest for CI and production. Do not depend on a moving tag for reproducible builds. Use WASI & containers if you specifically want a WASM-native container runtime rather than this native Linux image.
