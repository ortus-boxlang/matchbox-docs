Native Fusion lets you expose Rust functions and objects as BoxLang built-ins, then link them into the application. Use it for a measured hot path, a Rust library, or native capabilities that the standard runtime does not provide.

Project layout

hello-fusion/
├── app.bxs
└── native/
    └── math.rs

MatchBox detects a neighboring native/ directory and uses the fusion build path. Unlike an ordinary prebuilt-runner build, this needs a working Rust toolchain and suitable linker.

Expose a Rust function

In native/math.rs:

use matchbox_vm::{matchbox_fn, types::BxNativeFunction};
use std::collections::HashMap;

#[matchbox_fn]
pub fn add(a: f64, b: f64) -> f64 {
    a + b
}

pub fn register_bifs() -> HashMap<String, BxNativeFunction> {
    let mut functions = HashMap::new();
    functions.insert("add".to_string(), add_wrapper as BxNativeFunction);
    functions
}

The macro generates add_wrapper, including argument-count checks and conversions. Register the wrapper, not the original Rust function. Function names should be unique across your native modules.

Call it from BoxLang

In app.bxs:

println(add(10, 20)); // 30

Build and run:

matchbox --target native app.bxs
./app

Conversions & return values

The documented matchbox_fn macro supports parameters such as f64, i32, bool, String, and BxValue. Its documented wrapper uses a numeric return conversion. Use a manual BIF for other return types or validation that needs richer semantics.

A manual BIF has this shape:

fn my_function(
    vm: &mut dyn BxVM,
    args: &[BxValue],
) -> Result<BxValue, String>

Validate inputs at the Rust boundary instead of assuming every BoxLang call has the expected type or range.

Native objects

#[matchbox_class] and #[matchbox_methods] provide class/method integration. A register_classes() function registers constructors using a module.ClassName key. BoxLang can then instantiate them with syntax such as new rust:counter.Counter(0).

Target support

This guide demonstrates native builds. Current compiler source also includes target-specific fusion paths, but a Rust module and its dependencies must support the destination. Do not assume OS libraries, JNI, threads, or host I/O compile unchanged for WASM or embedded targets.

The original Native Fusion reference has more extensive macro examples, but its older native-only target statement does not describe every current compiler path. Prefer your checked-out implementation and test the final artifact.
