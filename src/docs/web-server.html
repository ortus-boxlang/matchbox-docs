MatchBox has two web hosting models. The webroot server serves static files and .bxm templates. The routed app server uses explicit routes and middleware. This guide covers the webroot model.

Create a webroot

Create a directory called www, then save this as www/index.bxm:

<bx:set name = "MatchBox">
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Hello MatchBox</title></head>
<body>
  <bx:output><h1>Hello, #name#!</h1></bx:output>
</body>
</html>

BoxLang Markup combines HTML with BoxLang tags and expressions. MatchBox transpiles BXM into executable bytecode. Static files such as CSS and images can live beside your templates.

Start the server

matchbox --serve --host 127.0.0.1 --port 8080 --webroot ./www

Visit http://localhost:8080. The default host is loopback and the default port is 8080. Press Ctrl + C to stop the process.

With the standalone server distribution:

matchbox-server --port 8080 --webroot ./www

Or from the source repository:

cargo run -p matchbox_server -- --port 8080 --webroot ./www

Request scopes

ScopePurpose
urlQuery-string parameters.
formSubmitted form data.
cookieRequest cookies.
sessionIn-memory session state.
cgiRequest and server metadata.

These scopes belong to web requests, not ordinary CLI scripts. In-memory sessions are not a distributed or durable persistence layer.

Deployment considerations

  • Only place public assets and intended templates in the webroot. Keep credentials and private source outside it.
  • Validate input and encode untrusted values for their output context; interpolation alone is not safe HTML escaping.
  • Use an appropriate TLS reverse proxy and process supervision for a public deployment.
  • Bind to 0.0.0.0 only when you intentionally need access beyond loopback or from a container port mapping.
