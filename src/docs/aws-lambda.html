Development workflow

The reviewed implementation supports local invocation and deployment, but deployment still requires an explicit Linux bootstrap binary. Do not assume every published release includes this command or an embedded Lambda runner.

Write a handler

Create Lambda.bx with a class exposing run(event, context, response):

class {
    function run(event, context, response) {
        response.statusCode = 200;
        response.headers = { "Content-Type": "application/json" };
        response.body = { "message": "Hello from MatchBox" };
    }
}

The runtime provides the raw AWS event, an AWS-style context, and a mutable proxy response. The application chooses status, headers, and body.

Invoke locally

Create event.json containing {} for this minimal handler:

matchbox lambda invoke Lambda.bx --event event.json

From a MatchBox source checkout, you can use cargo run -- lambda invoke … instead. Local invocation returns the proxy response; it does not create cloud infrastructure.

Deployment prerequisites

  • AWS CLI v2, configured credentials/profile, and a region.
  • An existing Lambda execution role with appropriate permissions.
  • A Linux Lambda bootstrap built for the function's architecture.

Deploying creates or updates AWS resources and may incur charges. Replace every example value before using this command:

matchbox lambda deploy Lambda.bx \
  --function my-matchbox-function \
  --role arn:aws:iam::123456789012:role/my-lambda-role \
  --profile my-profile \
  --region us-east-1 \
  --arch arm64 \
  --bootstrap /path/to/linux-arm64-bootstrap \
  --url

--url requests an IAM-authenticated Function URL. --public instead requests an unauthenticated URL that anyone can invoke; only enable that deliberately with appropriate application controls.
