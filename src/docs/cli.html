Usage

matchbox [options] [file.bxs|file.bxb|directory]
matchbox --help
matchbox --version

Without a file, MatchBox starts the REPL. Options vary by version and enabled Cargo features; your executable's --help is the final reference.

Compilation

OptionPurpose
--buildCompile to .bxb bytecode without executing.
--target nativeBundle a standalone native executable.
--target jsBuild a browser JavaScript module and WASM package.
--target wasmBuild raw browser-oriented WASM.
--target wasiBuild a server-side WASI command.
--target wasi-httpBuild a WASI HTTP component from --webroot.
--target esp32Produce firmware/bytecode for an ESP32 device.
--output <path>Override the artifact output path.
--strip-sourceRemove embedded source text, retaining file/line metadata.
--keep <symbols>Preserve a comma-separated list of functions during tree-shaking.
--no-shakingKeep the full prelude.
--no-std-libExclude the prelude entirely.
--module <path>Load a module directory; may be repeated.
--verboseEmit verbose build logging.

Webroot server

matchbox --serve --host 127.0.0.1 --port 8080 --webroot ./www
OptionDefault / purpose
--serveStart the built-in webroot server.
--host <address>127.0.0.1
--port <number>8080
--webroot <path>Current directory.

The routed server's --app option belongs to the separate server executable, not the main CLI's webroot mode:

matchbox-server --app app.bxs

Embedded tools

Option / commandPurpose
esp32-doctorCheck build/flash prerequisites.
--chip <name>Select the board's chip, such as esp32s3.
--full-flashFlash the full runner/firmware and program.
--flashUpdate bytecode after the initial firmware installation.
--watchWatch source changes and coordinate flashing/monitoring.
--esp32-webOpt into the embedded routed web build flavor.

--fast-deploy is deprecated; use --flash. See ESP32 & embedded before flashing hardware.

Lambda commands

matchbox lambda invoke Lambda.bx --event event.json
matchbox lambda deploy Lambda.bx --function my-function --bootstrap /path/to/bootstrap

Deployment additionally needs configured AWS access and an execution role when creating a function. See AWS Lambda for architecture, profile, region, and Function URL choices. Deployment changes cloud resources; local invocation does not.
