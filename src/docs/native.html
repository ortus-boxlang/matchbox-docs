Build a standalone executable

matchbox --target native hello.bxs

This produces hello on Linux/macOS or hello.exe on Windows. The executable bundles your bytecode with a native MatchBox runner.

./hello
No separate language runtime to install

Ordinary standalone applications do not require Java or a separate MatchBox installation. OS/architecture compatibility and system-library requirements still apply. Optional JNI integrations need a compatible JVM.

Control the output

matchbox --target native --output hello-app --strip-source hello.bxs

--output overrides the artifact path. --strip-source omits source snippets while preserving file/line metadata. Create any output directory before building into it.

How runner stubs work

  1. The compiler produces bytecode from your source.
  2. A prebuilt runner supplies the VM for a particular platform.
  3. MatchBox appends the program to the runner.
  4. At startup, the runner loads and executes the embedded program.

Binary size depends on enabled features, target, and application code. Older documentation's roughly 500 KB figure describes lean runner configurations, not a fixed size for every application or the full CLI.

Cross-platform distribution

Native output is platform-specific. Build and test for each intended OS and CPU architecture. The Fat CLI includes deployment stubs, but --target native does not take an arbitrary Rust target triple.

For a reliable release pipeline, run the build on each target platform, or build the appropriate MatchBox toolchain and runner using Rust cross-compilation. Installing a Rust target alone may not provide the required linker and system libraries.

rustup target add x86_64-unknown-linux-gnu
cargo build --release --target x86_64-unknown-linux-gnu

The command above builds MatchBox from its source checkout; it is not a direct cross-compilation flag for a BoxLang script. See building from source.

Tree-shaking & dynamic calls

MatchBox removes unused prelude functions from compiled programs. If a function is reached dynamically and the compiler cannot infer that use, preserve it explicitly:

matchbox --target native --keep arrayMap,arrayFilter hello.bxs

Use --no-shaking to retain the full prelude while diagnosing missing-function issues. --no-std-lib removes the prelude entirely and is an advanced size-control option.

Add Rust where you need it

Native Fusion compiles Rust code from a neighboring native/ directory and exposes it to BoxLang. Fusion builds need a Rust toolchain; plain stub-based builds are the simpler path when you do not need custom native code.

Is the JIT included?

The standard native CLI enables JIT compilation, while lean runner stubs are built without it. Do not use CLI timing as a promise of identical standalone performance. See JIT & architecture and benchmark the artifact you actually ship.
