The native app server is built around web.server() and ColdBox-style handlers. Use it for JSON APIs, microservices, explicit template routes, middleware pipelines, and WebSockets.

Your first route

Create app.bxs:

import boxlang.web;

app = web.server();

app.get("/hello/:name", function(event, rc, prc) {
    event.renderJson({ "message": "Hello, " & rc.name });
});

app.listen(8080);

The web namespace is host-provided, but scripts must explicitly import it.

Run the app server

matchbox-server --app app.bxs

From a source checkout, the package is named with an underscore:

cargo run -p matchbox_server -- --app /path/to/app.bxs

Visit http://localhost:8080/hello/MatchBox. The server distribution and Cargo-built binary may use different filenames; use the executable you built or downloaded.

Understand the handler

  • event provides request and response helpers.
  • rc is the public request collection, combining route, query, form, and top-level JSON object data.
  • prc is private request state for communication between middleware and handlers.

Treat rc as untrusted input. Validate the fields your application expects before using them.

Middleware

Register middleware before calling app.listen(). The fourth argument continues the pipeline:

app.use(function(event, rc, prc, next) {
    prc.requestStarted = true;
    next.run();
});

Middleware can affect headers, response bodies, status, cookies, and session state. Calling next.run() hands control to the next stage.

Templates & static assets

app.use(app.middleware.buildStaticFiles("/assets", "public"));

app.get("/", function(event, rc, prc) {
    event.setView("views/home.bxm", { "title": "MatchBox" });
});

The static directory is resolved relative to the application script. Missing files fall through to routing. Templates receive event, rc, prc, session, and viewArgs.

WebSockets

Register a configured listener instance with app.enableWebSockets("/ws", listener). SocketBox-style lifecycle methods include onConnect(channel), onMessage(message, channel), and onClose(channel).

Channels support text, JSON, and binary messages, broadcasts, and closing the connection. The WebSocket counter example includes a listener and browser client:

cargo run -p matchbox_server -- --app docs/examples/websocket_counter/app.bxs

Open http://localhost:8099 in two tabs to try the shared counter.

Native runtime scope

The native app server also supports route groups, cookies, in-memory sessions, and webhook builders. These features are not all available on ESP32. See the embedded limitations before moving an application to hardware.
