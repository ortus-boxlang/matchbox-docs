Choose the correct target

TargetPurpose
js / wasmBrowser-oriented WebAssembly. See the browser guide.
wasiServer-side command workloads using the WASI Preview 1 runner.
wasi-httpA WASI HTTP component built from a webroot, using the Preview 2 target.
A correction to older guides

Some early documentation used --target wasm for both browser and container use. The current CLI distinguishes wasm from wasi. Check your installed version's --help.

Build a WASI command

Create service.bxs containing println("Hello from WASI");, then build:

matchbox --target wasi service.bxs

Run the generated service.wasm with a compatible WASI runtime such as Wasmtime:

wasmtime run service.wasm

If the application needs file access, grant only the required directory:

wasmtime run --dir=. service.wasm

WASI permissions are host-controlled. Network APIs and other platform capabilities depend on both the MatchBox build and the host; native CLI capabilities do not imply identical WASI behavior.

Package a WASI HTTP webroot

matchbox --target wasi-http --webroot ./www --output site.wasm

This packages a prepared webroot into a WASI HTTP component. The source-build path needs the server feature, Rust's wasm32-wasip2 target, and the WASI HTTP runner:

rustup target add wasm32-wasip2

Run the output on a host that supports the appropriate WASI HTTP component interfaces. This is not the same as a normal Preview 1 command, and a plain wasmtime run command is not an HTTP hosting configuration.

WASM in OCI containers

A minimal image can contain just a WASI command:

FROM scratch
COPY service.wasm /service.wasm
ENTRYPOINT ["/service.wasm"]

You need a WASM-aware container runtime, such as an appropriate containerd runwasi shim. A default Docker runtime does not execute WASM simply because it is inside a container. Configure your chosen runtime according to its current documentation.

Portability is not identical capability

  • No JNI or JVM access in WASI.
  • No browser DOM or js.* bridge.
  • File and network access are constrained by the runtime and its permissions.
  • Cloudflare, Fastly, and other edge hosts have their own interfaces and packaging contracts. A generic WASI file is not a guaranteed one-command deployment to every provider.

If you simply need to run MatchBox inside a standard Linux container, the official native Docker image is the more direct path.
