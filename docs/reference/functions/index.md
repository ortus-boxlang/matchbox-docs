# Function reference

This reference lists the built-in functions found in the MatchBox 0.11.0 source tree. It is generated by `tools/gen-bif-reference.mjs` from the places where the runtime registers functions, so it does not drift from the code. Do not edit these pages by hand. For the meaning of a BoxLang function, see the [BoxLang documentation](https://boxlang.ortusbooks.com/).

## How to read the tables

| Column | Meaning |
| --- | --- |
| Function | The function name. Member-only entries are written `type.name`. |
| Forms | How to call it. `name( ... )` is the global form and `type.name( ... )` is the member form on a value of that type, for example `string.ucase( ... )`. A literal `...` means the argument list is not recorded here. Functions written in BoxLang show their real parameters. |
| Gate | `always`, or the cargo feature or crate that must be enabled for the function to exist. |
| Notes | Behavior notes. Text appears only where it was checked against the source or by running MatchBox. |

Function names are not case sensitive; the pages show the usual spelling.

## Counts

- Global functions: 610. 532 are native Rust functions, 55 are written in BoxLang (the prelude), 8 exist in both, 3 are handled by the compiler (println, print and echo; echo also exists as a native function) and 12 are TUI class names.
- ESP32 firmware functions: 29 (included in the global count above).
- Member functions on built-in types: 314.
- Native object methods: 226.
- Internal helper functions that only back the member table (`boxSet*`, `arrayAppendMember`) are not listed: 31.

## Feature gates

The default features of the root crate are `bif-io`, `bif-jni`, `bif-crypto`, `bif-cli`, `bif-http`, `jit`, `server`.
The browser playground is built from `playground-runtime/Cargo.toml`, which depends on the VM crate with default features turned off and no extra features, for the `wasm32-unknown-unknown` target. Only the `always` functions exist there.

Other features change behavior without adding functions:

- `qoq` (not default): enables query of queries. `queryExecute` with `dbtype: "query"` returns the error "QoQ support is not enabled in this build" without it.
- `bif-jni` (default): `createObject( "java", ... )` creates Java objects. Without it the call fails with "Java interoperability is not enabled in this build."

## Not available in the browser playground

143 of the 610 global functions are not available in the playground build: everything behind a gate in the table above, including the ESP32 functions and the TUI classes. Common examples are `hash`, `encrypt`, `fileRead`, `directoryList`, `http`, `queryNew`, `queryExecute`, `cliRead` and `exit`. Member functions whose target function is gated are unavailable there too, for example `string.hash( ... )`.

## Prelude functions called as members

Functions written in BoxLang (the prelude) are added to a program only when the compiler sees them used (tree shaking). A member call such as `[3,1,2].sort()` is resolved at run time, so the compiler does not see `arraySort` and, in a program run with `matchbox file.bxs`, the call fails with `BIF arraysort not found`. The same program works when it also references the function by name, or when it is run with `--no-shaking` or `--keep arraySort`. The browser playground loads the whole prelude, so members work there. Rows marked with this note are the prelude functions that have a member form.
